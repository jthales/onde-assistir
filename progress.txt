### GitHub Actions — Populate diário
- Criado `.github/workflows/populate.yml`
- Roda automaticamente todo dia às 10:00 UTC (07:00 BRT) via cron
- Permite execução manual pela aba Actions (workflow_dispatch)
- Variáveis de ambiente necessárias (configurar em Settings → Secrets):
  - GEMINI_API_KEY
  - FIREBASE_PROJECT_ID
  - FIREBASE_CLIENT_EMAIL
  - FIREBASE_PRIVATE_KEY (valor de uma linha com \n literais, igual ao Vercel)
- Logs em pt-br com emojis para identificar sucesso/falha
- Nome do workflow: "🎯 Populate Jogos Diário"

### Frontend — "Hoje" e "AO VIVO"
- Data do jogo exibe "Hoje" (em verde e negrito) quando o jogo é no dia atual (fuso BRT)
- Badge vermelho pulsante "● AO VIVO" aparece no lugar do horário quando o jogo está em andamento
- Lógica de detecção:
  - eHoje(): compara data do jogo com hoje em BRT (UTC-3)
  - eAoVivo(): combina data+hora com offset -03:00, considera ao vivo se passou do início e está dentro de 2h
- Arquivos alterados: app.ts, app.html, app.css

### Placar ao vivo com cache
- Nova rota GET /api/placar no backend
- Consulta ESPN API em tempo real (mesma fonte do populate)
- Cache em memória no servidor com TTL de 10s
- Fallback: se a ESPN falhar, serve o cache antigo
- Frontend faz polling a cada 10s, mas SOMENTE quando há jogo ao vivo (eAoVivo = true)
- Quando ao vivo: "VS" é substituído pelo placar (ex: 2 – 1) + tempo de jogo (ex: 45')
- Período exibido: "1T", "2T" ou "Intervalo"
- Placar não fica em vermelho (cor neutra #111827)
- ngOnDestroy limpa o interval ao sair da página
- Constantes compartilhadas (TEAM_NAME_MAP, espnScoreboardUrl) extraídas para backend/src/constants.ts
- Arquivos alterados/criados:

- Interface Gol adicionada em frontend/src/app/models/jogo.ts

### Odds Bet365 via ESPN Core API
- Novo endpoint GET /api/odds no backend
- Para cada jogo da semana, busca odds em paralelo via ESPN Core API:
  https://sports.core.api.espn.com/v2/sports/soccer/leagues/bra.1/events/{id}/competitions/{id}/odds
- Filtra pelo provider Bet365 (ID 2000)
- Cache de 5 minutos (odds mudam menos que placar)
- Retorna: mandante, empate, visitante (number | null)
- Frontend exibe bloco "Bet365 · 1.85 · 3.40 · 4.20" abaixo do onde-assistir nos cards
- Se todos os campos forem null, o bloco não é exibido
- Polling a cada 5 minutos no frontend (independente de jogo ao vivo)
- Interface Odds adicionada em frontend/src/app/models/jogo.ts
- Arquivos alterados: backend/src/index.ts, models/jogo.ts, jogos.service.ts, app.ts, app.html, app.css

### Correção: jogos no intervalo (Halftime)
- Problema: ESPN retorna statusName='Halftime' (distinto de 'In Progress')
- Backend mapeava Halftime para 'agendado' → placar não exibia corretamente
- Fix backend: Set com todos os estados em andamento:
  'In Progress', 'Halftime', 'End Of Period', 'Overtime', 'Shootout' → 'em-andamento'
- Fix backend: periodo retorna 'Intervalo' quando statusName='Halftime'
  (antes retornava '2T' incorreto, pois event.status.period já vale 2 no intervalo)
- eAoVivo() mantido como lógica puramente por horário (janela de 2h)
  (tentativa de usar status ESPN criava dependência circular que parava o polling)
- Arquivos alterados: backend/src/index.ts
